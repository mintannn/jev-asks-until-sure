# バレる。

質問に答えていくと、AIが**文章人格・出身地・年代・性格**を言い当てるアキネーター型の診断。
TypeSafe の System One モデル **Jev** で動いています。

```bash
npm run dev      # http://localhost:3000
```

`.env.local` に `TYPESAFE_API_KEY` が必要です（APIキーはサーバー側だけで扱っています）。

---

## これがJevのデモである理由

普通のアキネーターや LLM 診断では出せない3つが、そのまま体験になっています。

**1. 「診断中…」が存在しない**
ボタンを押した瞬間に全候補のバーが動きます。実測 **230〜440ms**。
LLM で同じことをやると1項目あたり数秒かかるので、この画面は作れません。

**2. 1リクエストで18問を同時評価**
毎ターン投げているのは1リクエストだけです。中身は:

| 質問 | 型 | 内容 |
| --- | --- | --- |
| `persona` | Choice | 110の人物像（絞り込み後は減る） |
| `prefecture` | Choice | 47都道府県 |
| `age` | Choice | 5つの年代 |
| `closing` | Choice | 最後の一言をどの文体で届けるか（14文体） |
| `trait_*` | Score ×8 | 承認欲求・自信のなさ・圧・建前度… |
| `verdict_*` | Noul ×8 | 「深夜に長文を書くタイプか」など |
| `next_question` | Choice | 次に聞くべき質問をモデル自身に選ばせる |

独立した質問は並列評価されるので、**質問を増やしてもレイテンシはほぼ変わりません**。
`next_question` は「続けるか止めるか決まる前」に投げている投機的な質問ですが、
どうせ同じ応答時間なので無駄になりません。

**3. confidence が「いつ言い切るか」を決める**
質問数は固定ではありません。確信したら5問で止まり、掴めなければ12問粘り、
それでも `confidence < 0.28` なら **「……わかりません。あなたは何者ですか？」** と降参します。
校正済み confidence を持つ Jev だからできる打ち切りで、この降参エンドは仕様です。

## 実装で踏んだ地雷と、その直し方

作る過程で壊れた箇所を、詰まった順に書いておきます。どれも Jev 側ではなく、
System One の使い方を僕が間違えていた話です。

### 1. 出身地が「東京」と「北海道」の2箇所に吸い込まれた（`route.ts` / `lib/geo.ts`）

実測するとこうなっていました。

| 与えた証拠 | 答え |
| --- | --- |
| 関西っぽい回答 | 大阪 64% ✅ |
| 首都圏っぽい回答 | 東京 55% ✅ |
| **九州っぽい回答** | **北海道 51%** ❌ |
| **東北っぽい回答** | 北海道 27%（秋田 6%） ❌ |
| **地域と無関係な回答** | 東京 51% ❌ |

**北海道＝「田舎・雪」の吸収先、東京＝「証拠なし」の吸収先**。原因は3つありました。

**(a) 47県ぜんぶ `criteria: null` で渡していた**

```ts
// これが元凶
Object.fromEntries(PREFECTURES.map((p) => [p, null]))
```

`criteria` はそのままモデルに渡す判定基準です。人物像には全部説明を書いたのに、
都道府県は県名だけ渡して「あとは察して」という状態になっています。判定材料がないので、
モデルは県名から連想できる既定のイメージに落ちるしかない。
`lib/geo.ts` に47県ぶんの手がかり（方言・雪・交通・食・都市規模）を書いて解消。

**(b) 47択では確率が薄く広がり、事前分布に負ける**

8択の地方判定を並列に足して、**地方の確率を事前分布として県に掛ける**ようにしました
（`combineGeo()`）。同じリクエスト内なのでレイテンシは増えません。

```ts
const r = Math.pow((regionProbs[REGION_OF[pref]] ?? 0) + 0.02, 0.5);
```

指数で鈍らせているのは、そのまま掛けると 100% に振り切れて
分布を眺める面白さが消えるからです。`+0.02` は、地方が否定した県にも芽を残すため。

**(c) 地域を切り分ける質問が足りなかった**

東西を分ける質問（エスカレーター、うなぎ）ばかりで、南北を分ける質問がありません。
「雪かきをしたことは？」「台風が近づいてきたら？」「家から海まで？」などを追加。

直した後:

| 与えた証拠 | 答え |
| --- | --- |
| 九州っぽい回答 | 福岡 91%（地方 九州・沖縄 100%） |
| 沖縄っぽい回答 | 沖縄 100% |
| 広島っぽい回答 | 広島 99% |
| 内陸っぽい回答 | 長野 52% / 山梨 16% |
| 東北っぽい回答 | 福島 51% / 北海道 38%（正直な拮抗） |

残りの2つも同時に直しました:

- **証拠を取りに行かせる**（`lib/questions.ts` の `QUOTA`）
  次の質問を Jev に選ばせると性格系ばかり選ぶので、**何を聞くかの枠はコードが決め**、
  Jev にはその枠の"中で"選ばせる。コードがワークフローを持つ、という原則そのまま。
- **質問ごとに関連する回答だけ渡す**（`instructions` を構造化オブジェクトにする）
  ```ts
  prefecture: {
    type: "choice",
    instructions: {
      地域に関する回答: turnsOfCat(turns, ["geo"]),   // ← geo の回答だけ
      question: "`地域に関する回答` だけを根拠に…",
    },
    criteria: prefectureCriteria,
  }
  ```

結果、「だべ」→北海道・秋田、「やん」→大阪60%、「蒸さないでしょ」→愛知、と正しく効くようになりました。

### 2. 110択だと confidence が構造的に上がらない

選択肢が多いと確率が薄く広がり、`confidence` が 0.2 前後から動きません。
このままだと全員が降参エンドになります。

**確率の薄い候補を毎ターン実際に脱落させる**ことで解決（`narrow()`）。
110 → 56 → 40 → 30 → … と減り、confidence が自然に上がります。
UI 側でも「候補 56 人」が減っていくのがそのまま演出になります。

ただし一気に絞ると1問目の思い込みが固定されて戻れなくなるので、
**4問目までは全員残す**＋上限を超えていても確率 2% 以上の候補は救済しています。

### 3. 誰がやっても同じ質問列になった

枠を固定順の配列にしていたうえ、`next_question` は「情報量が最大の質問」を選ぶので、
**構造的に毎回同じ**になっていました。2箇所を直しています。

- 枠の順番を固定配列から、**残り枠で重み付けした抽選**に（`pickCategory()`）
- Jev に候補を全部見せず、**ランダムに5問へ間引いてから**選ばせる（`CANDIDATE_SAMPLE`）

同じ回答者で3回走らせると、質問列も結果も別物になります。

### 4. Noul が全部 0.3 台に潰れた

`` `この回答者は、${v.text}か？` `` というテンプレートで
「〜タイプだ**か？**」という壊れた日本語を生成していました。
`instructions` は**それ自体で完結した疑問文**にして、`criteria` で yes/no の意味も渡す。

```ts
{
  type: "noul",
  instructions: "この回答者は、自分に非がない場面でも先に謝ってしまうタイプか？",
  criteria: { true: "衝突を避けるため反射的に謝る", false: "非がなければ謝らない" },
}
```

### 5. 誰をやっても「塩対応」と判定された

実測するとこうなります。

| 回答 | 塩対応 |
| --- | --- |
| うどん | **86%** |
| エスカレーターは左 | 58% |
| 電車 | 52% |
| よく喋る | 4% |

上4つは全部**地域質問**です。原因は2つ。

**(a) 人格判定に地域・年代の回答まで食わせていた**

県と年代には「関係する回答だけ渡す」を入れたのに、**人格だけやり忘れていました**。
「うどん」「電車」のような人格の情報を持たない回答まで見せると、
素っ気ない事実回答が「素っ気ない人」と読まれます。

**(b) 証拠がゼロでも無理やり選ばせていた**

(a) を直したら、今度は「絵文字が一個もない人」が40%で空席を埋めました。
「情報を出さない人」という定義が「情報がない状態」に一番マッチしてしまう。
**人格の証拠が1問も無いターンは、人格質問そのものを投げない**ようにして解決。

加えて、ルーブリックを「書き方」ではなく「どの選択肢を選ぶか」に書き換えました。
この診断は選択式なので、回答者は一文字も書きません。
「返事が一語で終わる」のような書き方の基準は、**構造上すべての人に当てはまります**。

```diff
- "塩対応": "返事が一語で終わる。絵文字も句読点も使わず、誘いも相談もそっけなく切る"
+ "塩対応": "誘いを断り、通知を切り、相談にも深入りしない。人との接触量そのものを減らす選択を一貫して選ぶ"
```

人格質問を12通り変えて試すと、**12通りとも違う人格**が出るようになりました
（塩対応は「グループLINEは通知を切ってる」でのみ88%）。

### 6. 年代も同じ理由で真ん中に吸われる

塩対応と同じ話が年代でも起きます。「立場ができ、時間の使い方がシビアになる」のような
人生段階の記述は、どの年代の人にもそこそこ当てはまるので、中央の年代が勝ち続けます。

```diff
- "30代": "立場ができ、時間の使い方がシビアになる"
+ "30代": "ガラケーと実家のPCの両方を通ってきた。句点は相手によって使い分ける。絵文字は1〜2個"
```

抽象的な人物評ではなく、**回答から観察できる事実**を書くと分かれます。
ルーブリックは「その人を describe する文」ではなく「回答と突き合わせる文」です。

## 地方（CHIHOU）というパラメータ

`region` は **8地方の Choice**。47県を一発で当てさせる代わりに置いた中間層です。

47択は確率が薄く広がって `confidence` が意味を持たなくなりますが、
8択なら集中します。この安定した地方判定を**事前分布として県に掛ける**ことで、
「田舎っぽい → 北海道」という吸収を潰しています。地方と県は同じリクエスト内で
並列に評価されるので、判定が1段増えてもレイテンシは変わりません。

画面には地方・県ともに分布をそのまま出し、さらに
**Jev に渡している `criteria` の本文**（`はんていきじゅん` ウィンドウ）を表示しています。

```
じんかく  オヂサン
  中年男性的な間合い。丁寧だが微妙にズレた言い回しと過剰な絵文字
ちほう    東北
  冬は豪雪で雪かきが日常。訛りが強い。車社会で、買い物は郊外の大型店
けん      北海道
  雪が日常で雪かきは毎年。「だべ」「なまら」。土地が広く車必須。梅雨がない
```

この文字列が判定のすべてです。`criteria: null` で渡していたときに何も当たらないのは、
ここが空だからです。

## 画面：思考ログを見せる

8bit の RPG UI にして、**コードが決めたことと Jev が決めたことを分けて実況**しています。
確信度は HP バー、候補は敵リスト、脱落はダメージ。
聞かなかった質問も「スキップした」と明示します。

```
出題ワクを ちゅうせん → 「ちいき」
ワクの 13問 から 5問 を Jev に提示
Jev が えらんだ（54%）：雪かきをしたことは？
こうほ 56 → 40  16にん だつらく！
ちいきの しょうこは ふえていない → ちほう・けんは スキップ
かくしんど 23 → 20 （-3）
```

確信度が上下に揺れるのは隠していません。証拠が増えるたびに評価し直しているので、
新しい回答が前の推測を否定すれば当然下がります。それが見えることに意味があります。

結果の言い方も確信度で3段階に変えています。

| 確信度 | 言い方 |
| --- | --- |
| 55%以上 | **わかりました！** と断定 |
| 28〜45% | **いいきれませんが……たぶん** と濁す |
| 28%未満 | **……わかりません。あなたは何者ですか？** と降参 |

## 文体は「書かせる」のではなく「選ばせる」

Jev はテキストを生成しません。なので最後の一言は、**14種類の台詞を人間が書いておいて、
Jev にどれを届けるか選ばせて**います（`lib/closings.ts`）。

この制約はむしろ都合がよくて、人が書いた台詞のほうが生成文より面白いし、
その中から選ぶのは Choice がまさに得意とする仕事です。

## コスト：毎回9,711トークン送って、変わるのは300トークン

料金は **$0.042 / Mtok（入力のみ。出力は無料）**。
ダッシュボードのトークン数は入出力の合計ですが、課金は入力だけなので、
請求額から逆算した入力トークンは合計の約82%になります（出力比は実測18%前後）。

単価ではなく**送っている量**に問題があります。1リクエストの内訳を実測するとこうです。

| ブロック | tok | 毎ターン変わるか |
| --- | --- | --- |
| persona 110択 | 3,919 | 絞り込みで減るだけ |
| prefecture 47択 | 2,007 | ❌ 地域質問に答えた時だけ |
| trait Score×8 | 847 | ❌ 結果画面でしか使わない |
| closing 14択 | 774 | ❌ 同上 |
| verdict Noul×8 | 730 | ❌ 同上 |
| region 8択 | 463 | ❌ 地域質問に答えた時だけ |
| age 5択 | 377 | ❌ 年代質問に答えた時だけ |
| next_question | 254 | ✅ |
| **state（実際の回答）** | **約300** | ✅ |

**9,711tok のうち、ターンごとに変わるのは約300tok だけ。**
「並列だからレイテンシが増えない」は本当ですが、**タダではありません**。
`criteria` はそのまま毎回送られて課金されます。

2つ直しました。

- **証拠が増えていない質問は投げない** — 地域質問に答えていないターンは、
  地域判定の入力が1文字も変わらない。同じ state に同じ質問を投げれば同じ答えが返るだけ
- **結果でしか使わない質問は、確定してから別リクエストで取る** —
  性格・所見・文体（2,351tok）を毎ターン聞いて11回捨てていた。往復が増えるのは最後の1回だけ

結果：**101,294tok → 48,814tok（-52%）、¥0.638 → ¥0.308**。

なお**本当の制約はコストではなくレート制限**で、1,200 req/分 ＝ **秒20発**です。
バズった場合はここが先に詰まります。
