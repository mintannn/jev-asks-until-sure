# バレる。

**AIが「あと何問聞けばいいか」を自分で決める**アキネーター型の診断。

文章人格・出身地・年代・性格を言い当てます。5問で確信すれば5問で止まり、
掴めなければ12問まで粘り、それでも分からなければ言い切らずに降参します。

> ……わかりません。あなたは なにものですか？

この「降参」があることが、このアプリの主題です。

🇬🇧 [English](./README.md) ・ 📓 [実装ノート](./docs/build-notes.ja.md) ・
TypeSafe の System One モデル [Jev](https://typesafe.ai) で動いています

---

## Jevのデモとして何が新しいか

分類モデルのデモは普通、ラベルと数字を出して終わります。でも Jev で本当に新しいのは
**「どれだけ分かっているか」をモデル自身が持っている**ことなのに、それが画面に出ない。

なのでここでは confidence をデバッグ値ではなく**ゲームの仕組みそのもの**にしました。
アキネーターにおいて「あと何問必要か」は、機能ではなく商品そのものです。

**質問数が固定ではありません。** 確信度55%以上なら言い切り、28〜45%なら
「いいきれませんが……たぶん」と濁し、28%未満なら答えを拒否します。
数字が変わるだけでなく、**言い方そのものが変わります**。

**「診断中…」が存在しません。** 1ターン1リクエストで実測230〜440ms。
ボタンを押した瞬間に全候補のバーが動きます。スピナーは一つもありません。

**考えている過程が見えます。** 思考ログが毎ターンを実況し、
**コードが決めたこと**と**Jevが決めたこと**を分けて書きます。

```
出題ワクを ちゅうせん → 「ちいき」
ワクの 6問 から 5問 を Jev に提示
Jev が えらんだ (76%)：雪かきをしたことは？
こうほ 110 → 64  46にん だつらく！
ちほう 九州・沖縄 97% で けん を おもみづけ
ねんだいの しょうこも ふえていない → スキップ
かくしんど 0 → 33 (+33)
```

確信度が**下がる**のも隠していません。毎ターン評価し直しているので、
新しい回答が前の推測を否定すれば当然下がります。そこが見えることに意味があります。

## 画面

8bitのRPG。確信度はHPバー、候補は敵リスト、脱落はダメージです。

- **ライブランキング** — 人格・出身県・地方を、前ターンとの差分つきで
- **110体のドット絵** — 1体が1候補。脱落すると暗くなる
- **判定基準** — ボタンで開くと、**いまJevに渡している `criteria` の本文そのもの**が出る
- **日本語 / English** — 右上で切り替え
- キーボード操作：`↑↓` と `Enter`、または数字キー

## Jevの使い方

1ターンにつき1リクエスト。最大18個の独立した判定が入っています。
並列に評価されるので、質問を増やしてもレイテンシはほぼ変わりません。

| 質問 | 型 | 内容 |
| --- | --- | --- |
| `persona` | Choice | 110の人物像（脱落すると減る） |
| `region` | Choice | 8地方 |
| `prefecture` | Choice | 47都道府県 |
| `age` | Choice | 5つの年代 |
| `closing` | Choice | 最後の一言をどの文体で届けるか（14文体） |
| `trait_*` | Score ×8 | 承認欲求・自信のなさ・圧・建前度… |
| `verdict_*` | Noul ×8 | 「深夜に長文を書くタイプか」など |
| `next_question` | Choice | 次に聞くべき質問 |

実際に効いているのは、この5つのパターンです。

**confidence を制御フローにする。** 打ち切り・濁し・降参は全部 `confidence` を
直接読んでいます。いつ終わるかを決めているのは他にありません。

**粗いChoiceを、細かいChoiceの事前分布にする。** 47択は確率が薄く広がって
confidence が意味を持ちませんが、8択の地方なら集中します。両方を同じリクエストで聞き、
地方の分布を県の分布に掛け合わせています。

**質問ごとに証拠を絞る。** `instructions` には構造化データを渡せるので、
1リクエストの中で質問ごとに別の証拠を見せられます。出身地の判定は地域質問の回答だけ、
人格の判定は性格質問の回答だけを見ます。

**ターン間で候補を脱落させる。** 確率の薄い候補を次のリクエストの `criteria` から
落とします。110択で confidence が上がるようになるのはこれのおかげです。

**生成させず、選ばせる。** Jev は文章を書かないので、最後の一言は14種類の台詞を
人が書いておいて、どれを届けるかだけ Jev に選ばせています。この制約はむしろ都合がよくて、
人が書いた台詞のほうが面白いし、その中から選ぶのは Choice が得意とする仕事です。

**投機的なファンアウト。** `next_question` は「続けるか止めるか」が決まる前に
投げています。並列評価なので、実時間ではタダです。

役割分担はこうなりました。**ワークフローはコード、判断は Jev。**
どのカテゴリから引くか、いつ止めるか、どの候補を落とすかはコード。
その枠の中でどの質問を選ぶか、あなたが何者かは Jev です。

## 数字

| | |
| --- | --- |
| レイテンシ | 1ターン 230〜440ms |
| コスト | 12問フルで ¥0.31 |
| 出身地の正解率 | 実測 12/16（約5問で47択を当てる） |
| 本当の制約 | コストではなくレート制限。1,200 req/分 ＝ 秒20発 |

証拠が変わっていない質問を投げないようにして、入力トークンを52%削っています。
これらの数字をどう出したかは[実装ノート](./docs/build-notes.ja.md)にあります。

## 意図的にやっていないこと

英語に切り替えても、変わるのは画面だけです。**Jev に送る `state`・`questions`・
`criteria` は常に日本語のまま**にしています。

全部日本語で測って詰めた数字なので、モデルへの入力を翻訳したらその保証が消えます。
なのでクライアントは英語を表示しつつ、送るのは日本語の回答文字列のまま。
判定基準の画面も、翻訳ではなく**実際に送っている日本語そのもの**を出しています。

## 動かす

```bash
npm install
echo "TYPESAFE_API_KEY=..." > .env.local
npm run dev
```

APIキーはサーバー側でのみ読まれます。

| ファイル | |
| --- | --- |
| `app/bareru.tsx` | 画面ぜんぶ |
| `app/api/diagnose/route.ts` | Jevへの問い合わせ、絞り込み、出題、打ち切り判定 |
| `lib/jev.ts` | System One の薄いクライアント（429/529 は指数バックオフ） |
| `lib/personas.ts` | 110の人物像・年代 |
| `lib/geo.ts` | 8地方と47都道府県の判定ルーブリック |
| `lib/questions.ts` | 質問バンク・配分・地域コア・性格軸・Noul |
| `lib/closings.ts` | 14文体の最後の一言 |
| `lib/i18n.ts` | UI文言 |
